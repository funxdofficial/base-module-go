# {{README_TITLE}}

Go cron/consumer service scaffold generated by [base-module-go](https://github.com/funxdofficial/base-module-go) (`base-module-go --pkg={{PKG_NAME}} --type=consumer`).

Background cron jobs via **golang-module-scheduler**. No HTTP server, routes, or controllers.

## Architecture

```
main.go
  ├── config.GetConfig()            # env-only config
  ├── module.Init(cfg)              # syslog bootstrap
  └── container.InitService(mod)
        └── service.Run()           # cron scheduler only
              ├── scheduler         # Tier 1 — cron job runner
              ├── usecase           # Tier 2 — business logic
              └── repository        # Tier 2 — data access
                    ├── model
                    ├── model/request
                    └── model/response
```

```

## Tier architecture

| Tier | Packages | Role |
|------|----------|------|
| **Tier 1** | `config`, `model`, `service`, `module`, `container` | Env config, domain entities, cron transport, DI |
| **Tier 2** | `model/request`, `model/response`, `service/usecase`, `service/repository` | DTOs and layered business/data logic |

**Wiring:** `repository → usecase → scheduler → service (cron)`

## Interface file naming

| Layer | Interface file | Implementation file |
|-------|----------------|---------------------|
| Repository | `repository/repository.go` | `repository/repository_<entity>.go` |
| Usecase | `usecase/usecase.go` | `usecase/usecase_<entity>.go` |

Interface files hold the `*InterFace` type and shared errors. Implementation files hold the concrete struct and entity methods.

## Quick start

```

The default `heartbeat` job runs every 5 minutes and logs the current item count from the in-memory repository.

## Cron / scheduler configuration

Jobs are defined in `config/config.go` (`Scheduler.Jobs`) and dispatched in `service/scheduler.go` (`runJob` switch).

Default job:

| Job name | Expression | Description |
|----------|------------|-------------|
| `heartbeat` | `00-00-0000 00-05-00` | Every 5 minutes — logs item count via usecase |

Expression format: `DD-MM-YYYY HH-MM-SS` (golang-module-scheduler).

## Configuration (.env)

Configuration is **env-only** — there is no YAML config file.

```bash
cp .env.example .env
```

| Variable | Default | Description |
|----------|---------|-------------|
| `SERVICE_NAME` | `{{PKG_NAME}}` | Service identifier |
| `APP_TIMEZONE` | `Asia/Jakarta` | Application timezone |
| `LOG_TYPE` | `console` | `console`, `file`, or `all` |
| `LOG_FILE` | `logs/app.log` | Log file path (when using file logging) |
| `LOG_BUFFER_SIZE` | `1000` | Async log buffer size |
| `SCHEDULER_ENABLED` | `true` | Enable cron jobs |
| `SCHEDULE_EXPRESSION` | `00-00-0000 00-05-00` | Cron expression for the first job |
| `SCHEDULE_TZ` | `Asia/Jakarta` | Scheduler timezone (read by golang-module-scheduler) |

## How to add a new entity

Copy the `item` scaffold across layers:

1. Add `model/<entity>.go`, `model/request/<entity>.go`, `model/response/<entity>.go`.
2. Add interface methods in `service/repository/repository.go`; implement in `repository_<entity>.go`.
3. Add interface methods in `service/usecase/usecase.go`; implement in `usecase_<entity>.go`.
4. Wire repository → usecase in `container/container.go`.

## How to add a new cron job

1. Add a job entry in `config/config.go` (`Scheduler.Jobs`).
2. Handle the job name in `service/scheduler.go` (`runJob` switch).
3. Delegate business logic to the appropriate usecase method.
